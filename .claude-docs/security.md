# Модель безопасности

## 1. Назначение

Файл читает аудитор безопасности перед проверкой диффа или репозитория. Он описывает **модель** —
границы доверия, инварианты и принятые риски, — а не перечень находок. Привязка инвариантов — к
символам, файлам и ключам конфига, а не к номерам строк.

## 2. Границы доверия

- **Рендерер ↔ главный процесс.** Проходит: preload `window.animeDb` (`native/window/preload.js`) и
  IPC-каналы `ipcMain.handle` в `native/`. Недоверенный вход: любой скрипт в рендерере и аргументы
  IPC-вызовов.
- **Сайт в браузере пользователя → `127.0.0.1`.** Проходит: HTTP на `APP_PORT` и WebSocket на
  `WS_PORT` (`app/Caddyfile`), OAuth-callback на `127.0.0.1:41813`. Недоверенный вход: запросы с
  чужих страниц (CSRF, DNS rebinding), параметры OAuth-callback.
- **Главный процесс Electron ↔ дочерние процессы** (frankenphp, meilisearch, qbittorrent-nox,
  PHP-консьюмеры Messenger, PowerShell/netsh). Запускаются через `spawn` в `native/supervisor/*` и
  `native/firewall.js`. Проходят: аргументы командной строки, окружение (ключ Meilisearch), конфиг
  `qBittorrent.ini` (`WebUI\Address`, `WebUI\LocalHostAuth`), код возврата. Недоверенный вход:
  вывод и коды возврата процессов.
- **PHP ↔ дочерние процессы** (ffprobe, PowerShell в `WindowsProcessLivenessChecker`, `attrib`,
  `php -l` в `ZipPluginInstaller`, `bin/console` в `PluginCacheWarmer`). Проходят: аргументы
  командной строки, вывод процессов. Недоверенный вход: пути и имена файлов из ФС и каталога,
  вывод процессов.
- **Плагины ↔ ядро.** Проходят: манифест, код, HTML, ассеты и настройки плагина. Недоверенный вход:
  всё, что приходит от плагина (HTML — только через санитайзер).
- **Исходящая сеть.** Проходят: реестр плагинов маркета, обновления приложения, запросы плагинов
  через HTTP-клиент ядра (`PluginHttpClientFactory`). Недоверенный вход: ответы удалённых серверов.

## 3. Инварианты

Ослабление любого инварианта — находка уровня blocker/major.

**Electron (`native/`)**
- Окна создаются с `contextIsolation: true` и `nodeIntegration: false` (`native/window/index.js`,
  `native/window/splash.js`).
- Навигация вне `127.0.0.1:port` перехватывается (`interceptExternalNavigation`: `will-navigate`,
  `will-redirect`), `setWindowOpenHandler` всегда возвращает `{ action: 'deny' }`.
- `openExternal` пропускает только схемы `http:` и `https:`.
- CSP выставляется из `native/content-security-policy.js` (`onHeadersReceived` на `defaultSession`).
- В дочерние процессы аргументы IPC попадают только элементами массива `spawn` (`phpCommand.run`),
  без shell.
- `shell:open-path` проверяет путь в главном процессе (`openStoragePath` в `native/shell/index.js`):
  путь канонизируется и открывается, только если это существующий каталог внутри настроенных
  хранилищ; список хранилищ главный процесс берёт у backend сам, а не из аргумента.
- `backup:restore-start` сводит `name` к `path.basename` внутри каталога бэкапов.
- `catalog:export-start` (`destinationDir`), `catalog:import-start` (`archivePath`), `import-v1:start`
  (`installationDir`) и `dialog:pick-file` (`filters`) передают аргументы дальше **без проверки в
  главном процессе**. Это расхождение с желаемой моделью, а не защита: считать эти каналы
  проверенными нельзя.
- Инвариант: существующие проверки не ослабляются; у нового IPC-канала аргументы проверяются в
  главном процессе, а не в рендерере.

**Локальный сервер (`app/`)**
- `bind 127.0.0.1` в обоих server-блоках `app/Caddyfile`.
- `trusted_hosts` в `app/config/packages/framework.yaml`.
- CSRF-токен на каждом изменяющем эндпоинте (`CsrfTokenManagerInterface`, id токена на действие).
- `ShellRequestGuard` (заголовок `X-AnimeDB-Shell` + loopback-`Host`) — первым действием в
  эндпоинтах, которые трогают путь в ФС по запросу оболочки.
- Дочерние процессы: `spawn` (Node) и `Process` (PHP) — с массивом аргументов, без shell.
- `escapeshellarg` для каждого пути, подставляемого в строку `exec`.
- Повышение прав (UAC) — только по явному действию пользователя в настройках и только в
  `native/firewall.js` (`applyIncomingConnections` → `buildElevatedNetshCommand`: `powershell.exe`
  с `Start-Process -Verb RunAs`, внутренний скрипт передаётся через `-EncodedCommand`). Всё, что
  попадает в повышаемый скрипт (в т. ч. `program=`), берётся из констант и путей главного процесса,
  но не из аргументов IPC и не из ответов backend; кавычки у `name=`/`program=` расставляет
  `quoteNetshArg`. Это граница выше «процесса с правами пользователя» (раздел 6).

**Плагины и обновления**
- Подпись реестра плагинов Ed25519 — `PluginRegistrySignatureVerifier`; sha256 ZIP маркета —
  `MarketAssetDownloader`.
- Защита от zip-slip — `ZipPluginInstaller::assertSafeEntryNames`.
- HTML плагинов проходит через `PluginHtmlSanitizer`.
- Подпись `latest.yml` проверяется в `native/updater` по ключам из `update-keys.json`.
- Аудит зависимостей — `scripts/security-audit.js` с `security-audit-baseline.json`.

## 4. Модель плагинов

Плагины — внешние источники метаданных. Модель описывает, **чем** доверие обосновано.

- Код плагинов Integration/Local исполняется в процессе ядра (`PluginLoader`). Изоляции нет, и она
  вне модели.
- Плагин из маркета доверен через подпись реестра + sha256 ZIP.
- Свой ZIP доверен через явное согласие пользователя (предупреждение «third-party source» +
  POST с CSRF-токеном), без подписи.
- PHPStan-гейт плагинов работает в CI монорепозитория плагинов; установщик приложения его не
  запускает.

## 5. Принятые риски

Находка, совпадающая с принятым риском и не ослабляющая его дальше, — не находка.

### Секреты пользователя открытым текстом

- Класс: хранение секретов без шифрования (appSecret, пароль прокси, токены плагинов).
- Почему принят: защита — права ФС профиля, как у остальных файлов данных приложения.
- Решение: #219, #657.
- Условие пересмотра: изменение выносит секреты за пределы профиля пользователя на этой машине — синхронизация или экспорт настроек с секретами, доступ к приложению не с `127.0.0.1`, многопользовательская установка.

### qBittorrent WebUI с `LocalHostAuth=false`

- Класс: неаутентифицированный локальный API на `127.0.0.1`.
- Почему принят: доступ только с loopback, приложение — единственный клиент.
- Решение: #345.
- Условие пересмотра: `WebUI\Address` перестаёт быть `127.0.0.1` (`seedConfig()` в `native/supervisor/qbittorrent.js`), порт WebUI попадает в правило файрвола (`native/firewall.js`) или WebUI получает второго клиента кроме `QbittorrentClient`; либо общее условие — доступ не с `127.0.0.1`, многопользовательская установка.

### Локальный HTTP-сервер без отдельной аутентификации

- Класс: отсутствие аутентификации.
- Почему принят: защита — изоляция `127.0.0.1`, приложение для одного пользователя.
- Решение: [decisions.md](decisions.md) (§«Связь бэкенда с Electron»), README.
- Условие пересмотра: `bind` в `app/Caddyfile` перестаёт быть `127.0.0.1`, появляется второй пользователь или клиент, кроме оболочки и браузера владельца (многопользовательская установка, удалённый доступ), либо эндпоинты начинают отдавать секреты.
